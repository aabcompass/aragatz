# camera_test_gen: руководство по генератору тестового потока

## 1. Назначение и версия документа

Генератор `camera_test_gen` имитирует камеру внутри PL. PS задаёт длину кадра, содержимое слов, среднюю скорость и расписание триггеров через AXI4-Lite. Генератор выдаёт поток независимо от состояния Capture и DDR. Запись в DDR выполняет `camera_capture`; собственного DDR-мастера у генератора нет.

Документ предназначен для Aragatz / Zynq-7000 / Vivado 2023.1. Адреса периферии в программах берутся из BSP `xparameters.h`. Пример текущего размещения генератора в Aragatz — `0x40010000`; этот адрес не зашит в RTL.

**Основание документа, 24 ноября 2026 года:**

- Полностью прочитаны RTL и существующие тесты репозитория `aabcompass/camera_test_gen`, commit **`ae34422674489ae22f03075a723ed6bf7e5b8a81`**. Ссылки на эти исходники приведены в разделе 16.
- Aragatz указывает другой submodule commit: **`6bd968297201383d788fcd744fac085e7f2e424b`**. Во время подготовки он был недоступен через GitHub: `No commit found for the ref`. Поэтому документ не утверждает побайтовое совпадение доступного RTL с текущим bitstream.
- В аппаратной сессии уже подтверждена правка декодирования адреса AXI-Lite в BD-адаптере. В доступном commit `ae344…` этой правки ещё нет; различие явно описано в разделе 3.
- Значение регистра `VERSION` — `0x00010000`. Оно идентифицирует программный интерфейс V1.0 и само по себе не различает commits или локальные исправления.

Далее описание регистров и поведения опирается на прочитанный RTL. Рекомендации по тестам и программному управлению отдельно обозначены как рекомендации. После публикации текущего submodule commit следует сверить его с этим документом и обновить строку основания.

## 2. Интерфейсы, тактирование и состав

### Внешние сигналы

| Интерфейс / сигнал | Направление относительно генератора | Содержание |
| --- | --- | --- |
| `clk` | Вход | Единственный тактовый домен. В Aragatz используется 200 МГц. |
| `rst` | Вход | Синхронный сброс, активный уровень 1. |
| `S_AXI` | Slave | AXI4-Lite, 32-битные адреса и данные, независимый приём AW и W. |
| `M_AXIS.TDATA[63:0]` | Выход | 64-битные слова камеры. |
| `M_AXIS.TVALID` | Выход | В этом такте выдано слово. |
| `M_AXIS.TLAST` | Выход | Последнее слово кадра; устанавливается только вместе с TVALID. |
| `M_AXIS_TRG.TDATA[63:0]` | Выход | Данные алгоритмического триггера. |
| `M_AXIS_TRG.TVALID` | Выход | Событие алгоритмического триггера. |
| `ext_trig` | Выход | Зарегистрированный импульс внешнего триггера. |
| `timestamp[63:0]` | Выход | Свободно работающий счётчик тактов. |

У обоих потоковых интерфейсов **нет TREADY**. Каждое слово при TVALID считается выданным; получатель обязан принять его в данном такте. Генератор не может ждать освобождения FIFO или DDR. `PAUSE` является командой PS, а не обратным давлением со стороны Capture. [R5, R6]

### Модули

| Модуль | Ответственность |
| --- | --- |
| `camera_gen_regs` | AXI-Lite, конфигурационные регистры, команды, чтение статуса и статистики. |
| `camera_gen_control` | Проверка START, рабочая копия конфигурации, RUNNING, курсор кадров/слов, счётчики. |
| `camera_gen_timing` | Выдача слов по дробной скорости NUM/DEN. |
| `camera_gen_pattern` | COUNTER или CONSTANT. |
| `camera_gen_trigger` | Расписание событий, алгоритмический канал и внешний импульс. |
| `camera_test_gen` | Соединение перечисленных модулей и 64-битный timestamp. |
| `camera_test_gen_bd` | Module Reference для Vivado и регистровая ступень на выходах потоков. |

### Регистровая ступень в BD

Адаптер одновременно задерживает на один такт пять сигналов: данные, TVALID и TLAST камеры, данные и TVALID алгоритмического триггера. Их взаимное соответствие сохраняется, включая случай триггера на последнем слове кадра.

`ext_trig` уже зарегистрирован внутри `camera_gen_trigger`, поэтому адаптер не добавляет ему ещё одну ступень. Внутри Capture этот сигнал проходит собственную синхронизацию. Нельзя считать момент обнаружения внешнего триггера равным моменту обнаружения алгоритмического триггера.

`timestamp` подключён напрямую и продолжает считать такты. Он не является зарегистрированной меткой каждого слова AXIS. После STOP или PAUSE уже выданное внутреннее слово может ещё находиться в выходной ступени адаптера. [R4–R6]

## 3. Адресация AXI-Lite

Все смещения в этом документе отсчитываются от базы генератора. Используются выровненные 32-битные обращения.

В `camera_gen_regs` декодируются **локальные смещения**: старшие биты адреса `[31:8]` должны быть нулевыми, младшие `[1:0]` — нулевыми. Поэтому в интеграции с полным системным адресом адаптер должен передавать ядру локальный адрес.

Для текущего 64-КиБ окна Aragatz аппаратно использована правка:

```verilog
.s_axi_awaddr({16'd0, s_axi_awaddr[15:0]}),
.s_axi_araddr({16'd0, s_axi_araddr[15:0]}),
```

Она относится к входам AXI-Lite генератора. База окна должна быть выровнена по 64 КиБ; изменение организации адресного пространства требует повторной проверки адаптера. В прочитанном commit `ae344…` эти два адреса ещё передаются напрямую. Правка подтверждена историей аппаратных запусков Aragatz, а не данным commit. [R1, R6]

Поведение slave:

- AW и W могут приходить независимо, в любом порядке.
- Для записи поддерживаются `WSTRB[3:0]`: изменяются выбранные байты.
- Чтение неизвестного или невыровненного адреса возвращает `SLVERR`.
- Запись неизвестного, невыровненного или read-only регистра возвращает `SLVERR`.
- Ошибка содержимого допустимого конфигурационного регистра не вызывает ошибку самой записи: значение сохраняется, а допустимость проверяется при START.
- `AWPROT` и `ARPROT` не участвуют в проверке адреса или конфигурации.
- Успешный ответ AXI-Lite на запись START означает, что запись команды обработана. Принятие START проверяется через STATUS. [R1, R2]

## 4. Полная карта регистров

Обозначения: **RW** — чтение/запись; **RO** — только чтение; **W1P** — запись единицы формирует однотактовую команду. Reset — значение после аппаратного сброса.

| Смещение | Регистр | Доступ | Reset | Значение / допустимый диапазон |
| --- | --- | --- | --- | --- |
| `0x00` | COMMAND | W1P, чтение 0 | 0 | bit0 START, bit1 STOP, bit2 CLEAR_STATS. |
| `0x04` | PAUSE | RW | 0 | bit0: 1 — приостановить выдачу; применяется немедленно. Остальные биты отбрасываются. |
| `0x08` | MODE | RW | 0 | 0 COUNTER, 1 CONSTANT. |
| `0x0C` | FRAME_WORDS | RW | 96 | 1…65535 слов по 64 бита в кадре. Для текущего Capture — 96. |
| `0x10` | RATE_NUM | RW | 24 | 1…65535; NUM ≤ DEN. |
| `0x14` | RATE_DEN | RW | 125 | 1…65535. |
| `0x18` | CONSTANT_LO | RW | 0 | Биты `[31:0]` постоянного слова. |
| `0x1C` | CONSTANT_HI | RW | 0 | Биты `[63:32]` постоянного слова. |
| `0x20` | TRIG_MODE | RW | 1 | 0: выкл.; 1: алгоритмический; 2: внешний; 3: оба. |
| `0x24` | TRIG_FIRST_FRAME | RW | 128 | Индекс первого триггерного кадра, 32 бита, отсчёт от 0. |
| `0x28` | TRIG_PERIOD_FRAMES | RW | 128 | 0 — одно событие; иначе период в кадрах, 32 бита. |
| `0x2C` | TRIG_WORD | RW | 0 | Индекс слова: 0…FRAME_WORDS−1. |
| `0x30` | EXT_WIDTH | RW | 4 | 1…255 тактов clk. |
| `0x34` | STATUS | RO | 0 | RUNNING, PAUSED, CFG_ERROR, START_BUSY; см. ниже. |
| `0x38` | FRAME_INDEX | RO | 0 | Индекс текущего/следующего формируемого кадра, 32 бита. |
| `0x3C` | WORD_INDEX | RO | 0 | Индекс следующего слова, биты `[15:0]`; верхние биты 0. |
| `0x40` | WORDS_SENT | RO | 0 | Количество выданных слов, modulo 2³². |
| `0x44` | FRAMES_SENT | RO | 0 | Количество завершённых кадров, modulo 2³². |
| `0x48` | ALG_COUNT | RO | 0 | Количество алгоритмических событий, modulo 2³². |
| `0x4C` | EXT_COUNT | RO | 0 | Количество запросов внешнего импульса, modulo 2³². |
| `0x50` | LAST_TRIG_FRAME | RO | 0 | Индекс кадра последнего разрешённого события. |
| `0x54` | TIMESTAMP_LO | RO | 0 | Младшие 32 бита текущего timestamp. |
| `0x58` | TIMESTAMP_HI | RO | 0 | Старшие 32 бита текущего timestamp. |
| `0x5C` | VERSION | RO | `0x00010000` | Программный интерфейс V1.0. |

**Разрядности рабочих полей не являются масками записи.** Кроме PAUSE, конфигурационные регистры сохраняют все записанные 32 бита. Например, запись `0x00010001` в FRAME_WORDS не превращается в 1: последующий START отклоняется. Только после проверки допустимости выбранные поля копируются в рабочие 16- или 8-битные регистры. [R1, R2]

### COMMAND

| Маска | Команда | Действие |
| --- | --- | --- |
| `0x00000001` | START | Попытка начать новый запуск и принять конфигурацию. |
| `0x00000002` | STOP | Снять RUNNING. |
| `0x00000004` | CLEAR_STATS | Очистить статистику и диагностические флаги. |

COMMAND выполняется только при `WSTRB[0]=1`. Биты `[31:3]` игнорируются; чтение всегда возвращает 0. Если одновременно записаны START и STOP, STOP имеет приоритет. CLEAR_STATS обрабатывается независимо. Практическая рекомендация — записывать каждую команду отдельным обращением. [R1, R2]

### STATUS

| Бит | Маска | Имя | Смысл |
| --- | --- | --- | --- |
| 0 | `0x1` | RUNNING | Запуск активен. |
| 1 | `0x2` | PAUSED | `RUNNING && PAUSE`. |
| 2 | `0x4` | CFG_ERROR | Неверная конфигурация при попытке START; sticky. |
| 3 | `0x8` | START_BUSY | START был запрошен при RUNNING=1; sticky. |

Биты `[31:4]` читаются как 0. Флаги CFG_ERROR и START_BUSY очищаются аппаратным сбросом или CLEAR_STATS. Успешный последующий START сам по себе их не очищает. Установленный старый CFG_ERROR не блокирует корректный START. [R1, R2]

## 5. Жизненный цикл: START, PAUSE, STOP, очистка

### Конфигурация и START

Регистры MODE…EXT_WIDTH являются **теневой конфигурацией**. Чтение этих регистров возвращает записанную теневую копию; отдельного чтения рабочих копий нет. Изменения во время RUNNING относятся к следующему успешному START. PAUSE — исключение: он действует на текущую выдачу. [R1, R2]

START разрешён, когда RUNNING=0 и одновременно выполнены условия:

- MODE ∈ {0, 1}.
- 1 ≤ FRAME_WORDS ≤ 65535.
- 1 ≤ RATE_NUM ≤ RATE_DEN ≤ 65535.
- 0 ≤ TRIG_MODE ≤ 3.
- TRIG_WORD < FRAME_WORDS.
- 1 ≤ EXT_WIDTH ≤ 255.

TRIG_WORD и EXT_WIDTH проверяются **даже при выключенном соответствующем источнике триггера**. TRIG_FIRST_FRAME и TRIG_PERIOD_FRAMES могут иметь любое 32-битное значение.

Успешный START:

1. Копирует теневую конфигурацию в рабочие регистры.
2. Сбрасывает FRAME_INDEX и WORD_INDEX в 0.
3. Перезапускает фазу дробного генератора скорости.
4. Заново устанавливает расписание триггеров.
5. Устанавливает RUNNING.

**START не очищает WORDS_SENT, FRAMES_SENT, ALG_COUNT и EXT_COUNT.** Для независимых запусков сначала выполняют CLEAR_STATS при остановленном генераторе, затем START. Аппаратная вставка `start_accepted` подавляет преждевременную выдачу во время запуска; число слов не следует рассчитывать по времени завершения AXI-записи команды. [R2, R3, R5]

### PAUSE

При PAUSE=1 не выдаются новые слова, фаза скорости и курсор кадра/слова сохраняются. После PAUSE=0 поток продолжается со следующего слова. RUNNING остаётся равным 1. Повторный START во время PAUSE устанавливает START_BUSY, поскольку генератор продолжает считаться запущенным.

PAUSE не останавливает timestamp. Уже начатый внешний импульс продолжает отсчитывать EXT_WIDTH; он не растягивается паузой. Новое триггерное событие возможно только вместе с новым выданным словом. Выходная ступень BD может завершить выдачу ранее сформированного слова после изменения PAUSE. [R2–R6]

### STOP

STOP снимает RUNNING без ожидания TLAST. Последний кадр может оказаться неполным. Слово, совпавшее с обработкой STOP, может быть учтено, а зарегистрированный выход BD требует времени для завершения уже сформированной выдачи.

Курсор и статистика сохраняются. Следующий успешный START начинается заново с кадра 0, слова 0; продолжение прежнего курсора обеспечивается PAUSE/RESUME, а не STOP/START.

При штатной остановке **активного Capture** сначала запрашивают STOP у Capture и продолжают подавать поток до его предусмотренного завершения. Затем останавливают генератор. Когда Capture уже закончил заданные фрагменты и перешёл в END, генератор можно остановить непосредственно. [R2, R6; последовательность для Capture — рекомендация интеграции]

### CLEAR_STATS

Очищает:

- WORDS_SENT, FRAMES_SENT.
- ALG_COUNT, EXT_COUNT.
- LAST_TRIG_FRAME.
- CFG_ERROR, START_BUSY.

Не очищает конфигурацию, PAUSE, RUNNING, курсор кадра/слова, фазу скорости, timestamp и расписание триггеров.

При CLEAR_STATS во время потока статистическое событие, совпавшее с очисткой, не прибавляется к сбрасываемому счётчику, хотя курсор продолжает двигаться. Для однозначной проверки полного запуска очищайте статистику в остановленном состоянии. [R2]

## 6. Формат потока

### COUNTER, MODE=0

Каждое 64-битное слово имеет вид:

```text
bits [63:32] = frame_index
bits [31:16] = 0
bits [15:0]  = word_index
```

При обычном little-endian размещении 64-битного слова в DDR:

- `Xil_In32(address)` возвращает word_index.
- `Xil_In32(address + 4)` возвращает frame_index.

Например, кадр 128, слово 47:

```text
64-битное значение: 0x00000080_0000002F
байты по возрастанию адреса: 2F 00 00 00 80 00 00 00
```

Счёт начинается с кадра 0 и слова 0. На выдаче слова FRAME_WORDS−1 устанавливается TLAST, WORD_INDEX переходит в 0, FRAME_INDEX увеличивается на 1. Межкадровый специальный интервал отсутствует: следующие слова определяются тем же дробным расписанием. [R2, R3, R5, R7]

### CONSTANT, MODE=1

Все слова равны `{CONSTANT_HI, CONSTANT_LO}`. Курсор, TLAST, скорость, триггеры и статистика продолжают работать.

Пример: CONSTANT_HI=`0x01234567`, CONSTANT_LO=`0x89ABCDEF` даёт слово `0x01234567_89ABCDEF`. При проверке DDR младшее 32-битное значение находится по меньшему адресу. [R7]

### Длина кадра

Генератор допускает 1…65535 слов. Это возможность самого генератора. Для текущей конфигурации Aragatz Capture принимает кадры из **96 слов × 8 байт = 768 байт**. Проверка генератора с другой длиной не означает, что Capture сможет корректно обработать этот поток.

Значения TDATA при TVALID=0 не являются переданными словами и должны игнорироваться. [R2, R5]

## 7. Скорость и расчёты

При активном потоке без PAUSE генератор фазы формирует NUM слов за DEN тактов в установившейся работе. Промежутки между словами выбираются накопителем фазы; это не пакет из NUM подряд идущих слов с последующей общей паузой. При NUM=DEN выдаётся одно слово каждый такт. [R3]

Для частоты `f_clk`:

```text
слов/с   = f_clk × RATE_NUM / RATE_DEN
байт/с   = 8 × f_clk × RATE_NUM / RATE_DEN
кадров/с = f_clk × RATE_NUM / (RATE_DEN × FRAME_WORDS)
```

Расчётные значения при 200 МГц и 96 словах в кадре:

| NUM/DEN | Млн слов/с | МБ/с, десятичные | Кадров/с | Среднее время кадра |
| --- | ---: | ---: | ---: | ---: |
| 6/125 | 9,6 | 76,8 | 100 000 | 10 мкс |
| 12/125 | 19,2 | 153,6 | 200 000 | 5 мкс |
| 24/125 | 38,4 | 307,2 | 400 000 | 2,5 мкс |
| 1/2 | 100 | 800 | 1 041 666,67 | 0,96 мкс |
| 1/1 | 200 | 1600 | 2 083 333,33 | 0,48 мкс |

Это **скорость входного потока генератора**. Таблица не является результатом измерения устойчивой записи Capture в DDR. Для такой оценки нужны отдельные аппаратные испытания с проверкой данных, FIFO, ошибок и пропусков.

Счётчики 32-битные. Например, WORDS_SENT при 24/125 переполняется примерно за 111,85 с непрерывной выдачи; при 1/1 — за 21,47 с. Длительный тест должен учитывать modulo 2³² или собирать программные 64-битные приращения достаточно часто.

## 8. Триггеры

### Расписание

Событие возникает только на реально выданном слове, когда одновременно:

```text
FRAME_INDEX == next_trigger_frame
WORD_INDEX  == TRIG_WORD
```

Первый кадр задан TRIG_FIRST_FRAME. При ненулевом периоде следующие индексы равны `first + k × period`. При периоде 0 после первого события расписание выключается. При переполнении 32-битного сложения next_frame+period расписание также выключается; случайного перехода к началу диапазона нет. PAUSE задерживает событие вместе с потоком. [R4]

Для 96 слов допустимы, в частности:

- TRIG_WORD=0: первое слово кадра.
- TRIG_WORD=47: внутренняя точка кадра, использованная в V2.
- TRIG_WORD=95: последнее слово, одновременно с TLAST.

Для проверки предыстории Capture выбирают первый триггер достаточно поздним, чтобы Capture успел синхронизироваться и накопить нужное число полных кадров. В V2 использованы first=128 для предыстории до 64 кадров. [Аппаратная конфигурация V2]

### Алгоритмический канал

TRIG_MODE bit0 включает `M_AXIS_TRG`. Payload события:

```verilog
{32'h54524752, frame_index}
```

Младшие 32 бита — номер триггерного кадра, старшие — маркер `0x54524752`. Алгоритмический триггер соответствует тому же слову камеры, поскольку оба потока проходят общую регистровую ступень BD. В отсутствие события TVALID=0; внутри ядра TRG TDATA тогда равно 0. [R4–R6]

### Внешний импульс

TRIG_MODE bit1 включает `ext_trig`. Каждое событие запускает высокий уровень на EXT_WIDTH полных тактов. При 200 МГц:

```text
EXT_WIDTH=1   → 5 нс
EXT_WIDTH=4   → 20 нс
EXT_WIDTH=255 → 1275 нс
```

Повторный запрос до окончания импульса перезапускает отсчёт его ширины. При недостаточном промежутке импульсы могут слиться в один высокий уровень. EXT_COUNT считает **запросы**, а не число фронтов, увиденных Capture. Для раздельных импульсов оставляйте хотя бы один низкий такт между ними; практическое условие — расстояние событий не менее EXT_WIDTH+1 тактов. [R4]

При TRIG_MODE=3 оба типа событий формируются по одному расписанию. Это не даёт гарантии одновременного обнаружения обоих событий внутри Capture: внешний путь имеет собственную синхронизацию. Проверяйте каждый источник отдельно перед испытаниями их арбитража.

## 9. Статистика и согласованные снимки

FRAME_INDEX и WORD_INDEX описывают **следующую позицию выдачи**. FRAMES_SENT считает завершённые кадры. После последовательности CLEAR_STATS → START, до переполнений и без очистки во время потока:

```text
FRAME_INDEX == FRAMES_SENT
WORDS_SENT == FRAMES_SENT × FRAME_WORDS + WORD_INDEX  (modulo 2^32)
```

После дополнительного START без CLEAR_STATS или CLEAR_STATS посреди кадра эти равенства в общем случае неверны. [R2]

Отдельные регистры читаются отдельными AXI-транзакциями. При работающем потоке FRAME_INDEX, WORD_INDEX и счётчики могут измениться между чтениями. Для строгой проверки остановите либо приостановите генератор, дождитесь обработки команды и выхода последнего слова из BD-ступени, затем читайте снимок. PAUSE не останавливает timestamp и не гарантирует, что Capture уже закончил DDR-транзакции.

LAST_TRIG_FRAME=0 само по себе не означает отсутствия событий: событие могло быть на кадре 0. Используйте соответствующий счётчик.

### Почему ALG_COUNT может превышать число фрагментов

Генератор не получает сигнал «Capture закончил» и не прекращает расписание после последнего фрагмента. PS обычно сначала замечает END при опросе, затем записывает GEN STOP. Между этими действиями возможны дополнительные события.

В успешно пройденной V2 использовались first=128, period=128:

| Фрагментов Capture | Завершено кадров GEN | ALG_COUNT | Событий после нужного числа |
| ---: | ---: | ---: | ---: |
| 2 | 400 | 3 | 1 |
| 4 | 800 | 6 | 2 |
| 16 | 2400 | 18 | 2 |

Проверка `ALG_COUNT == requested_fragments` для такого запуска неверна. Следует проверять Capture по его собственным результатам, а генератор — по расписанию и стабильному курсору.

Для короткого запуска без переполнений, с очищенной перед START статистикой, числом завершённых кадров F и индексом следующего слова W:

1. Посчитать все запланированные события на кадрах строго меньше F.
2. Добавить событие текущего кадра F, если этот кадр входит в расписание и `W > TRIG_WORD`.
3. Для выключенного алгоритмического канала ожидаемый ALG_COUNT равен 0.

Второй пункт нужен, если STOP оборвал кадр после триггерного слова, но до TLAST. Триггер на последнем слове уже учитывается среди завершённых кадров.

## 10. Timestamp

Timestamp увеличивается каждый такт после снятия аппаратного сброса. START, STOP, PAUSE и CLEAR_STATS его не сбрасывают. При 200 МГц один тик равен 5 нс.

TIMESTAMP_LO и TIMESTAMP_HI не образуют аппаратный snapshot. Для согласованного значения при чтении PS используйте high–low–high с повтором, если старшие половины различаются:

```c
static uint64_t gen_timestamp(void)
{
    uint32_t hi1, lo, hi2;
    do {
        hi1 = gen_read(0x58U);
        lo  = gen_read(0x54U);
        hi2 = gen_read(0x58U);
    } while (hi1 != hi2);
    return ((uint64_t)hi1 << 32) | lo;
}
```

Функции gen_read/gen_write из следующего раздела используют реальные BSP-примитивы. Timestamp, записанный в преамбулу Capture, соответствует моменту его фиксации в Capture. Он не должен точно совпадать с более поздним чтением текущего GEN timestamp процессором. Для проверки его точности нужна отдельная проверка разностей и задержек. [R1, R5]

## 11. Пример управления из PS с xparameters.h

Ниже — функции управления только генератором для bare-metal BSP. Они не настраивают Capture, DDR или UART. Базовый адрес берётся из сгенерированного заголовка.

```c
#include <stdint.h>
#include "xparameters.h"
#include "xil_types.h"
#include "xil_io.h"
#include "sleep.h"

#ifndef XPAR_CAMERA_TEST_GEN_BD_0_BASEADDR
#error "Generator base address is missing from this BSP xparameters.h"
#endif

#define GEN_BASE ((UINTPTR)XPAR_CAMERA_TEST_GEN_BD_0_BASEADDR)

static uint32_t gen_read(uint32_t offset)
{
    return (uint32_t)Xil_In32(GEN_BASE + (UINTPTR)offset);
}

static void gen_write(uint32_t offset, uint32_t value)
{
    Xil_Out32(GEN_BASE + (UINTPTR)offset, value);
}

static int gen_wait_status(uint32_t mask, uint32_t value,
                           unsigned timeout_us)
{
    unsigned i;
    for (i = 0U; i < timeout_us; ++i) {
        if ((gen_read(0x34U) & mask) == value)
            return 0;
        usleep(1U);
    }
    return -1;
}

/* Call directly when Capture is idle or already completed.
 * An active Capture may need more camera data to finish its own STOP. */
static int gen_stop(void)
{
    gen_write(0x00U, 2U);
    if (gen_wait_status(1U, 0U, 1000U) != 0)
        return -1;
    usleep(1U); /* More than the one-cycle BD stream latency at 200 MHz. */
    return 0;
}

/* Leaves the generator configured and stopped. */
static int gen_prepare_counter(uint32_t first, uint32_t period,
                               uint32_t trig_word)
{
    if (trig_word >= 96U || gen_stop() != 0)
        return -1;

    gen_write(0x00U, 4U);       /* CLEAR_STATS */
    gen_write(0x04U, 0U);       /* PAUSE off */
    gen_write(0x08U, 0U);       /* COUNTER */
    gen_write(0x0CU, 96U);
    gen_write(0x10U, 24U);
    gen_write(0x14U, 125U);
    gen_write(0x20U, 1U);       /* algorithmic trigger */
    gen_write(0x24U, first);
    gen_write(0x28U, period);
    gen_write(0x2CU, trig_word);
    gen_write(0x30U, 4U);
    return 0;
}

/* Capture must already be armed and ready to receive the stream. */
static int gen_start(void)
{
    gen_write(0x00U, 1U);
    if (gen_wait_status(1U, 1U, 1000U) != 0)
        return -1;
    return (gen_read(0x34U) & 0xCU) == 0U ? 0 : -1;
}
```

Рекомендуемая последовательность полного теста:

1. Убедиться, что предыдущий Capture завершён; привести оба блока в исходное состояние.
2. Выбрать зарезервированный диапазон DDR, исключённый из ELF/stack/heap.
3. Подготовить шаблон памяти и выполнить требуемое обслуживание кэша перед записью PL.
4. Вызвать `gen_prepare_counter(first, period, word)`.
5. Настроить Capture и запустить его; дождаться готовности принимать поток.
6. Вызвать `gen_start()`.
7. Дождаться END или ошибки Capture с конечным timeout.
8. При нормальном END вызвать `gen_stop()`, прочитать стабильные счётчики.
9. Выполнить обслуживание кэша перед чтением DDR и проверить преамбулы, все слова данных и guard.
10. При timeout сохранить диагностические регистры. Не превращать неопределённое состояние активного Capture в новый запуск без предусмотренного завершения или сброса.

Для текущей аппаратной регрессии используйте готовые функции тестового приложения: они дополнительно проверяют размеры буфера, состояние Capture и формат фрагментов. Приведённый код показывает интерфейс генератора, а не заменяет всю регрессию.

## 13. Диагностика

| Наблюдение | Что проверить |
| --- | --- |
| MMIO-чтение VERSION не завершается или вызывает исключение | Соответствие BSP/XSA/bitstream, clk/rst, окно адресов, преобразование полного адреса в локальное смещение в BD-адаптере. |
| START не включает RUNNING | CFG_ERROR и все диапазоны конфигурации, включая EXT_WIDTH и TRIG_WORD при выключенных триггерах. |
| START_BUSY=1 | START был записан, когда RUNNING уже был 1, в том числе при PAUSE=1. |
| RUNNING=1, данные не движутся | PAUSE, очень малая NUM/DEN, подключение AXIS и тактирование. |
| Записанный MODE изменился, поток остался прежним | Читается теневая конфигурация; рабочая сменится при следующем успешном START. |
| Счётчики не начинаются с нуля | Перед START не выполнен CLEAR_STATS либо он выполнен во время потока. |
| Последний кадр после GEN STOP неполный | STOP не дожидается TLAST; для продолжения без обрыва используйте PAUSE. |
| ALG_COUNT больше числа фрагментов | Проверить расписание до фактического GEN STOP; Capture мог закончить раньше. |
| EXT_COUNT больше обнаруженных внешних фронтов | Проверить слияние импульсов, синхронизацию, разрешение источника и активное состояние Capture. |
| Timestamp имеет скачок на чтении PS | Прочитать high–low–high; две отдельные половины не являются snapshot. |
| Данные PS выглядят устаревшими | Проверить адрес зарезервированного буфера, завершение записи Capture и обслуживание кэша. |
| На высокой скорости появляются пропуски/ошибки | Зафиксировать профиль скорости, состояние FIFO и ошибки Capture; TREADY у генератора отсутствует. |

## 14. Границы функциональности

Текущий генератор поддерживает COUNTER и CONSTANT, дробную скорость, PAUSE, алгоритмический и внешний триггеры. В прочитанном RTL отсутствуют:

- PRBS, случайные данные и случайные интервалы.
- Программируемая порча TLAST или длины отдельных кадров.
- Автоматическая остановка после заданного количества кадров.
- Программируемая независимая задержка алгоритмического и внешнего событий.
- Обратное давление TREADY.
- DDR-мастер, встроенная проверка содержимого DDR, Ethernet или lwIP.
- Аппаратная инъекция AXI-ответов DDR.
- Аппаратный атомарный snapshot всех счётчиков.

Подключение к реальной камере, устойчивость всего DDR-тракта на предельной скорости и передача данных по Ethernet проверяются отдельно.
