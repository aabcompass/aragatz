## Что добавляет версия из этой ветки

Поддержка находится в `ps_sw/lwip_capture/phy/`. Она применяется к **одному GEM и одному KSZ9031 RGMII** в standalone BSP с `linkspeed=autodetect`. Штатные функции выбора частоты GEM сохраняются; значения делителей берутся из сгенерированного `xparameters.h` и существующей настройки PS.

* Сканируются MDIO-адреса **0…31**, читаются оба регистра идентификации. Принимается `ID1=0x0022`, `ID2 & 0xfff0 = 0x1620`. Отсутствие PHY, несколько KSZ9031 и ошибки MDIO не приводят к выбору случайного адреса. Адрес 0 является обычным адресом, а не запасным «broadcast».
* Перед настройкой проверяются BMCR и ANAR. Reset, loopback, power-down и isolate не снимаются автоматически. Установка этих битов требует проверки платы и штатной последовательности её запуска.
* Рекламируются 10/100/1000 **full duplex**; asymmetric pause отключается согласно Microchip DS80000692D, module 1. Существующая политика master/slave и symmetric pause сохраняется.
* Link и завершение autonegotiation определяются по BMSR с двойным чтением. Итоговые скорость и duplex берутся из регистра `0x1f`, а не только из общей рекламы возможностей. Half duplex, противоречивые биты скорости и link-check-fail отклоняются.
* Первоначальное ожидание ограничено 100 опросами с паузой 100 мс. Сам вызов дополнительно тратит время на MDIO. После первоначальной настройки монитор линка только читает состояние; он не повторяет длительное ожидание и не перезапускает autonegotiation при каждом опросе.
* Низкоуровневые `XEmacPs_PhyRead/Write` получают конечный бюджет ожидания MDIO — 100000 чтений регистра состояния на транзакцию. Это ограничение числа операций, **не гарантированный таймаут в микросекундах**.
* Значение ошибки не используется как скорость GEM. Кэш действительной скорости обновляется после renegotiation и проверяется перед восстановлением GEM после ошибки.

Настройки PHY reset GPIO, MMD skew, FLP, reference clock и PS preset автоматически не меняются. В частности, настройки KSZ9021 нельзя переносить на KSZ9031 как эквивалентные. Для проверки RGMII timing нужны схема/strap-настройки платы и расположение задержек TX/RX; без них численные значения не подставляются.

## Подготовка BSP

Создайте отдельное приложение **lwIP Echo Server**, standalone на `ps7_cortexa9_0`, из используемой XSA. Аппаратные тесты оставьте отдельным приложением. Для первого прохода используйте IPv4 и статический адрес; согласуйте адрес ПК и платы. В BSP выберите raw API и `linkspeed=autodetect`.

Найдите именно исходники BSP, который будет собираться для этого приложения. Пути зависят от имени platform/domain и версии пакета `libsrc`; не редактируйте одноимённую копию от другого проекта. Типовые окончания путей:

```text
libsrc/lwip213_*/src/contrib/ports/xilinx/netif/
libsrc/emacps_*/src/xemacps_control.c
```

Адаптерный скрипт принимает каталог с тремя штатными файлами. Проверка ожидает следующие Git blob SHA после нормализации переводов строк:

| Файл | Исходный blob `xilinx_v2023.1` |
| --- | --- |
| `xemacpsif_physpeed.c` | `8ccc7ba895b9513679abfa029408e55bae78ebd9` |
| `xemacpsif_hw.c` | `5f13438759251827cbf3f2aa0dd9c1065eb726b6` |
| `xadapter.c` | `feffb83184d9db171666dfbc046c01891db1be7e` |
| `xemacps_control.c` | `4c72f20e2154ae647e2b4f79d891ec8681fd4afb` |

Пример из корня Aragatz; замените два пути на пути своего BSP:

```bash
NETIF=/path/to/bsp/libsrc/lwip213_VERSION/src/contrib/ports/xilinx/netif
EMACPS=/path/to/bsp/libsrc/emacps_VERSION/src

python3 ps_sw/lwip_capture/phy/apply_adapter_patch.py "$NETIF"
python3 ps_sw/lwip_capture/phy/apply_adapter_patch.py "$NETIF" --diff
python3 ps_sw/lwip_capture/phy/apply_adapter_patch.py "$NETIF" --output-dir ksz9031-overlay
python3 ps_sw/lwip_capture/phy/apply_mdio_timeout.py "$EMACPS/xemacps_control.c" --output-file ksz9031-driver/xemacps_control.c
```

Скрипты создают новые файлы отдельно от BSP. Они отклоняют неизвестную или уже изменённую версию; опции принудительного применения нет. Для вашей первой копии `xemacpsif_physpeed.c` исходный hash подтверждён; два соседних файла и файл драйвера должны пройти проверку на вашей установке.

Замените в собираемом BSP три соответствующих файла содержимым `ksz9031-overlay/`, а драйвер — содержимым `ksz9031-driver/xemacps_control.c`. Сохраните исходные копии. Затем выполните **Clean/Build BSP**, затем Clean/Build приложения. Проверьте build log: компилируется именно этот `libsrc`, без второй копии функций. Готовые review diff также находятся рядом: `xilinx_v2023.1-ksz9031.patch` и `xilinx_v2023.1-mdio-budget.patch`.

При регенерации BSP Vitis может восстановить штатные исходники. После неё заново примените overlay к восстановленной штатной версии и пересоберите BSP. Для постоянной сборки можно хранить изменённые пакеты в локальном software repository Vitis; не смешивайте две методики в одном BSP.

## Первый запуск: echo и PHY/link

Сначала запустите штатное echo-приложение с этим BSP. Подключите кабель к ПК/коммутатору с согласованными сетевыми настройками. В UART должны быть видны обнаруженный адрес и ID, затем фактическая скорость. Ожидаемый формат сообщений, **не результат измерения этой платы**:

```text
KSZ9031 detected: address <0..31> ID 0022:162x
KSZ9031: auto-negotiation, full duplex only
link speed for phy address <addr>: <10|100|1000>
```

Проверьте бинарный echo через порт 7:

```bash
python3 host/aragatz_client.py echo 192.168.10.10 --port 7
```

Зафиксируйте UART и скорость порта на стороне ПК. Затем проверьте отключение/подключение кабеля и восстановление echo. При согласовании 100 или 10 Мбит/с запишите именно это значение, проверьте кабель/партнёра и RGMII-настройку. Принудительный `linkspeed=1000` не является исправлением autonegotiation.

Для расширенного дампа доступны `aragatz_phy_scan()` и `aragatz_phy_dump()` в `phy_diag.c`. Они читают регистры через уже инициализированный GEM и не меняют PHY. Вызывайте их из main-context с сериализованным доступом MDIO, например после `xemac_add` и до включения таймерных прерываний. `phy_diag.c` требует символ `aragatz_ksz9031_read_speed` из нового BSP: ошибка линковки этого символа означает, что overlay не попал в собираемую библиотеку.

После успешного echo используйте capture-приложение из [основной инструкции](../ps_sw/lwip_capture/README.md). В нём периодический опрос PHY и обслуживание RX перенесены из timer ISR в главный цикл. Таймер выставляет флаги; основной цикл вызывает `aragatz_platform_poll()`. Это обеспечивает последовательный доступ к MDIO вместе с `ar_phy_link_info()`.

## Проверки без платы и пределы этих проверок

Из корня репозитория:

```bash
cc -std=c11 -Wall -Wextra -Werror ps_sw/lwip_capture/phy/tests/test_ksz9031_mock.c -o phy_mock
./phy_mock
cc -std=c11 -Wall -Wextra -Werror ps_sw/lwip_capture/phy/tests/test_discovery.c -o phy_discovery
./phy_discovery
python3 ps_sw/lwip_capture/phy/tests/test_mdio_budget.py
python3 ps_sw/lwip_capture/phy/tests/test_recovery.py
```

`test_recovery.py "$NETIF"` дополнительно применяет преобразование к полным штатным исходникам и проверяет извлечённые функции. Без аргумента используются точная исходная функция восстановления с лицензией AMD/Xilinx и тот же включаемый код монитора, который вставляет overlay.

Эти проверки действительно выполнены для версии в ветке: поиск на всех 32 адресах; отсутствие, неоднозначность и неверная модель PHY; 10/100/1000 full duplex; latch-low BMSR; отклонение half duplex/некорректного BMCR; ошибки и частично выполненная конфигурация MDIO; ограничение ожидания; восстановление линка и кэша скорости. Это модели регистров на ПК. Сборка полного BSP в Vitis, реальный MDIO/RGMII, echo и скорость Ethernet требуют платы и ещё не подтверждены.
